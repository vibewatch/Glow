# 三工作区摄影计划架构

审查与实施日期：2026-08-03

## 结论

霁光不再采用“十个平级工具”的产品结构。霞光、雾、太阳、月亮、星空、彩虹和极光都在回答同一个问题：所选日期有哪些可拍窗口。云层、降雨和风则是对任意窗口的常规天气解释；日食、月食和流星雨属于不同时间尺度的事件日历。

因此产品只有三个顶层工作区：

```text
共享上下文：坐标 + 所选日期 + 所选时刻 + 数据生成时间
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
       每日拍摄机会    天气工作台     天象事件
        9 个窗口      云 / 雨 / 风   食象 / 流星雨
            └────────────┼────────────┘
                         ▼
              同一地图、来源和错误恢复
```

三个入口切换不会换页、丢失地点或重新请求已有天气。地图点击或拖动观测点后，所有工作区由同一份新响应更新。

## 状态模型

客户端共享状态分为：

- `workspace`: `opportunities | weather | events`
- `selectedIndex`: 七天天气日期
- `selectedOpportunityId` 与 `selectedInstant`
- `weatherTime` 与 `weatherView: cloud | rain | wind`
- `selectedEventId`
- 当前地点、天气加载状态和独立空间天气状态

每日机会列表、时间轴节点和地图方向从同一个 `DailyOpportunity` 生成，避免三个区域各自推导导致时间或方位漂移。每项显式包含：窗口起/峰/止、`scoreType`、机会指数或几何语义、可信度、状态、限制、详情和可选方向。

## 每日机会时间轴

时间轴分为两层：

1. 7 日日期 tabs，支持左右方向键、Home、End 和 roving `tabIndex`。
2. 00:00–24:00 日内轴，展示白昼背景、选中窗口、9 个峰值节点和 15 分钟原生 range 游标。

朝霞/晚霞、日出/日落保持独立 ID；夜间窗口允许跨午夜，右侧起止时间使用真实本地时刻。选中机会后地图只展示它的完整方位线与标签；没有可靠方位的雾景和普通星空只保留观测点。彩虹标的是“建议观察方向”，不是雨幕或彩虹所在位置。

地图方位当前仅用一个 DOM overlay，已经移除此前与 MapLibre GeoJSON 方向线重复绘制的双轨实现。线段长度只为可读性服务，不表达距离。

## 天气真实性边界

浏览器内的 `forecastForLocation()` 直接请求 Open-Meteo 并计算一个坐标的 168 小时时序，足以提供成熟的点位天气体验：

- 24 小时天气选择和 7 日日期切换。
- 总云与低/中/高云垂直结构。
- 降水概率、小时量、连续性雨、阵雨和天气代码。
- 持续风、阵风、来风方向和脚架风险。
- 温度、露点差、能见度和气压。

它不足以绘制区域云图、雷达雨图或风场。只有在接入具有授权、时间戳和空间分辨率说明的栅格/瓦片服务后，才能增加地图天气图层；不得把单点数据插值成看似真实的区域面。

## 极光独立降级

普通天气和空间天气使用独立的浏览器数据链路，没有本地 API 或后端：

- `lib/browser-data.ts` 的 `forecastForLocation()`：Open-Meteo 交付的 ECMWF、CMA、GFS、ICON 与 CAMS，加浏览器内 Astronomy Engine；当前页面缓存最多 20 个地点、有效期 10 分钟，中国时间跨日失效。
- `spaceWeatherForecast()`：NOAA SWPC planetary K-index forecast，15 分钟页面内存缓存；不可用结果最多缓存 2 分钟。

NOAA 响应会验证时间、Kp 范围和状态字段，并兼容当前对象数组与历史表格数组两种公开格式。上游失败时返回显式 `unavailable` 合同，不影响普通天气。

新地点取消旧请求，旧结果不能覆盖新地点；手动刷新绕过内存与浏览器 HTTP 缓存。坐标在发出上游请求前通过中国支持区校验。无共享缓存或服务端限流，配额由公开数据源控制；访问者需要能直接访问允许 CORS 的数据源。静态版本仅使用非商业开放端点，不支持私有 provider API 密钥。

本地极光机会同时使用 Kp、纬度经验门槛、天文黑夜和星空天气。由于尚未接入极光椭圆、太阳风 Bz 和现场暗空，可信度封顶且始终显示限制。超出 Kp 有效时间的日期不评分。

## 天象事件精度

- 食象由 Astronomy Engine 搜索下一个峰值在地平线上的本地事件。
- 主要流星雨目录给出活跃期、预计峰值夜、IMO 理想 ZHR、辐射点赤经/赤纬和观察建议。
- 浏览器按定位点计算峰值夜的最佳夜间观测时刻、辐射点高度与方位，并计算月面照明。
- 流星雨的 `peakPrecision` 固定为 `night-range`，界面不声称分钟级峰值。
- 事件日期只有落入当前 7 日响应后才附加天气；否则只显示几何和“尚无可信天气”。

## 扩展契约

新增每日机会必须进入 `DailyOpportunity` 适配器、时间轴和机会列表；新增天气详情必须共享小时游标；新增天象必须进入按峰值日期排序的统一事件类型。任何新增项都必须补充：

- 纯函数和降级测试。
- 浏览器数据合同或数据源验证，包括 CORS、请求取消、缓存和失败状态。
- 桌面/移动交互和 Axe 扫描。
- 8 视口截图矩阵。
- 语义单位、时效、来源和不能证明的内容。

`npm run verify:audit` 当前核对 3 个工作区、22 个 Playwright 流程和 82 张 UI 状态截图。

## 静态交付

Next.js 使用 `output: "export"`，`app/layout.tsx` 不依赖请求上下文，`out/` 不含天气 API。GitHub Actions 验证并发布该目录到 `https://glow.genisisiq.com`。构建后为每个 HTML 的内联启动脚本生成 SHA-256 CSP 哈希，并在脚本之前插入 CSP meta；内联事件和未受信任脚本被拒绝。防嵌入、HSTS、COOP 等仅响应头支持的策略由静态托管平台控制，不能由 CSP meta 替代。
